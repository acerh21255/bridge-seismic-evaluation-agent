# 第三步 → 第四步数据交接合同 2.0

第三步（建模与数值验算）按本合同交付数据，第四步（工程报告撰写 Agent）检查数据、执行判定并按实验室模板生成报告。机器校验以 `contracts/handoff.schema.json` 为准；填报从 `contracts/handoff.template.json` 开始；完整示例见 `examples/golden/76K278+308/handoff.json`（76K278+308 原报告逐表抽取）。

单位：力 kN，弯矩 kN*m（报告写作 kN·m），位移 m，无量纲 ratio。轴力正压负拉，须在 `analysis.axial_sign` 声明。

## 1 交付形式

- **zip（推荐）**：根目录 `handoff.json`，图件放在 `assets/`，`assets[].path` 写相对路径。上传时服务端校验路径，拒绝 `..`、绝对路径和符号链接；上限 50 MB。
- **单个 JSON**：可以判定并出报告，但图件无法随附，报告以“图件待补充”占位。

## 2 字段组

| 字段组 | 必交 | 内容 | 用途 |
|---|---|---|---|
| `contract_version`、`data_kind`、`bridge_id`、`model_revision`、`scenario` | 是 | 合同版本 2.0；数据性质（engineering_input / reference_reproduction / synthetic_variant）；原状模型版本 | 版本隔离、封面注记 |
| `project` | 是 | 路线、工程名、桩号、封面桩号行、题注桥名简称、跨径行、桥型、报告名、单位、日期、页眉 | 封面、页眉、题注 |
| `overview`、`codes` | 否 | 桥梁概况、桥墩构造说明、研究内容、立面图与构造图资产；参考规范清单 | 第 1、2 章 |
| `seismic` | 否 | 烈度、PGA、场地类别、Tg、设防类别、性能目标、反应谱参数（Tg、Ci、Cs、Cd、A、Smax）、时程波条数/持时/步长、波谱与时程图 | 第 3、4 章；反应谱图由程序按参数绘制 |
| `materials` | 否 | 材料说明、是否新老规范换算、混凝土表、钢筋表（表格为 header + rows） | 第 3 章 |
| `model`、`modal` | 否 | 软件、节点单元数、线性边界表、六弹簧刚度、支座说明与参数（类型、μd、Fmax、xy、初始刚度）、振型周期与振型图 | 第 5 章 |
| `analysis` | 是 | `converged`（未完成不得判定）、`axial_sign`、`methods.E1/E2` | 判定前提、报告表述 |
| `components` | 是 | 墩、桩、支座（及可选措施、盖梁、系梁）；`label`；方向；桩基 `parent_pier` | 构件范围 |
| `scope_review`、`selection` | 是 | 范围确认与证据；典型截面选择依据 | 可追溯 |
| `actions` | 是 | 同一工况的成组内力 N/M（E1 截面承载力必须关联） | 防止拼接不同工况极值 |
| `checks` | 是 | 逐项验算记录，见第 3 节 | 判定与验算表 |
| `not_applicable` | 否 | 不适用声明（构件、方向、水准、类型、理由、证据） | 不阻断流程 |
| `detailing` | 是 | 一级梁端边距（设计值、要求值）；二级、三级措施逐条（条款、要求、本桥设计、是否满足、主题） | 第 6.4 节 |
| `pilecap` | 否 | 必要性说明；斜压杆、拉杆、冲切明细（名称/单位/数值）与需求、承载力 | 承台验算表 |
| `retrofit` | 否 | 加固模型版本、方案说明与图、复核范围、加固后验算记录 | 第 8 章 |
| `assets`、`sources` | 是 | 图件清单（id、路径、题注、SHA256、宽度）；证据（inline 校验内容哈希、file 校验文件哈希、external 仅登记） | 图件、追溯 |

## 3 验算记录 `checks[]`

| kind | 构件 | 水准 | demand / capacity | 其他要求 |
|---|---|---|---|---|
| `e1_capacity` | 墩、桩 | E1 | 最不利轴力 N / 截面承载力 Nu（kN） | `paired_N_M`、`action_id`、`method=constant_eccentricity` |
| `e2_moment` | 墩、桩 | E2 | 弯矩 / 等效屈服弯矩（kN*m） | `axial_kN`；桩基超限且桥墩塑性时附 `overstrength` |
| `shear` | 墩、桩 | E2 | 剪力 / 抗剪能力（kN） | `axial_kN`；可附 `overstrength`（复算剪力） |
| `bearing_displacement` | 支座 | E1、E2 | 位移 / 规范限值（m） | 无规范限值时 `capacity=null`、`limit_status=not_provided` |
| `bearing_sliding` | 支座 | E1、E2 | 需求 / 抗力（kN） | 不适用时写 `not_applicable` |
| `hinge_shear` | 墩 | E2 | 剪力 / Vn（kN） | `phi`（如 0.9，判定采用 φVn） |
| `ductility_displacement` | 墩 | E2 | 位移需求 / 容许位移（m） | 仅进入塑性的墩与方向 |
| `ductility_reinforcement` | 墩 | E2 | 最小配箍率 / 实配配箍率（ratio） | 同上 |
| `measures`、`additional` | 措施、盖梁、系梁 | E1、E2 | 按验算内容 | `title` 说明验算内容 |

每条记录须有 `component`、`section_label`（如“1#墩底”）、`direction`、`level`、`unit`、`model_revision`、`evidence`，建议写 `locator`（证据中的表号或文件位置）。同一构件、方向、水准、类型只能有一条记录。数值缺失填 `null`，判定为待补正。

`overstrength`：`{"basis": "system_equilibrium", "reviewed": true, "evidence": "...", "factor": 1.2, "demand": 复算后内力}`。第四步只检查依据、复核与证据，不自行套系数。

## 4 第四步的检查与判定

- 合同级（任一不通过即只出补正通知）：Schema、分析完成、范围确认、证据哈希、构件引用与方向、单位、非负有限数、记录重复、模型版本混用、E1 配对与成组内力一致、不适用声明与记录冲突、加固版本必须不同。
- 判定级：按《项目说明》第 3 节流程逐项判定；缺记录或缺数值为待补正；中断规则只有 E1、桩基屈服、墩桩抗剪三类。
- 报告级：章节资料缺失以占位呈现并在自检中列出；图件缺失以“图件待补充”占位。

## 5 接入步骤建议

1. 以一座桥（建议 53K271+730）的一个控制截面导出完整记录，人工核对单位与符号。
2. 补齐全部构件与方向，上传 zip 在工作台运行，逐项核对“待补正与自检”。
3. 用 `tools/compare_golden.py` 的方法对照该桥原报告，确认数值与章节一致。
4. 再接入 MATLAB 计算结果与超强复算，最后扩展到其他桥。
