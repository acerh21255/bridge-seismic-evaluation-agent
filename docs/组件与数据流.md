# 组件与数据流

本文件说明统一仓库中四个组件的职责边界、输入输出和联调方式。详细的工程算法和关键规则见 [`系统技术说明.md`](系统技术说明.md)。

## 1. 端到端边界

| 边界 | 上游输出 | 下游输入 | 载体 |
|---|---|---|---|
| 图纸识别 → 筛选 | 五张复核工作表 | 台账记录与字段候选 | Excel |
| 筛选 → 建模 | 入选名单与全字段宽表 | 筛选表 / 参数 JSON | Excel / JSON |
| 建模 → 报告 | 参数、模型、验算结果与会话 | 交接合同 2.0 | `handoff.json` + `assets/` |
| Agent → 交付 | 判定、诊断、报告和建议 | 人工复核 / 工程签发 | DOCX、HTML、JSON、MD |

第 1、2 步之间的 Excel 字段字典位于
[`skills/bridge-drawing-recognition/assets/field_dictionary.csv`](../skills/bridge-drawing-recognition/assets/field_dictionary.csv)。
第 2、3 步的筛选表版式和参数 JSON 契约见
[`skills/bridge-seismic-pipeline/references/schema.md`](../skills/bridge-seismic-pipeline/references/schema.md)。
第 3、4 步的正式合同见
[`contracts/handoff.schema.json`](../contracts/handoff.schema.json)。

## 2. 运行模式

### 图纸识别

- 纯本地确定性模式：台账检查、归一化、页面清单、缩略图、Schema 检查。
- 视觉增强模式：由宿主注入 `analyze_image(...)` 工厂；所有候选保留证据和复核状态。
- 无后端时禁止伪造字段抽取结果。

### 代表性筛选

- 知识型执行：宿主读取 Excel，完整加载 15 条标准后完成评分、覆盖审计和交接表提取。
- 不把试用权重宣称为专家最终结论；不把低分解释为桥梁不安全。

### 建模与验算

- dry-run：记录 SAP2000 OAPI 指令，并使用规范简化法输出 E1/E2 演示验算。
- `--real`：连接本机 SAP2000 OAPI，保存模型并运行分析；首次使用须核对 OAPI 签名。
- 两种模式的假定值、警告和数据性质都必须随结果交付。

### 报告与决策

- 离线演示：固定工具链由脚本模型驱动，不需要外部 API。
- 在线模型：支持 OpenAI Chat Completions、OpenAI Responses 和 Claude Messages 兼容接口。
- 无论何种模式，工程数值和判定都由确定性引擎产生。

## 3. 联调顺序

1. 用第 1 步生成并人工核对台账候选。
2. 用第 2 步确认目标数量、整桥身份和建模单元，输出全字段交接表。
3. 用第 3 步生成参数和验算结果；按第 3→4 步合同整理 `handoff.json`。
4. 用第 4 步工作台导入 JSON 或交接 ZIP，先通过合同与资料检查，再执行判定和报告生成。
5. 人工复核报告、建议、假定值、证据路径与回执哈希，完成工程签发流程。

## 4. 不应跨越的边界

- 图纸 OCR 候选必须经人工确认后才能进入建模。
- 简化验算不得表述为 SAP2000 有限元结果。
- 桥梁筛选结果不得被表述为结构安全结论。
- 大模型不得修改 `result.json` 中的需求、能力、比值或判定状态。
- 任务执行完成不等于桥梁验算通过，`engineering_release=false` 不得在交付时省略。
