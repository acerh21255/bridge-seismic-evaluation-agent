# 维护说明

## 当前结构

运行入口为 Start-Demo.ps1 / bridge_report.server.app。静态前端没有 npm 构建步骤。模型协议适配集中在 bridge_report/agent/models.py；模板校验和上传资料处理在 bridge_report/server/assets.py。工程判定规则在 engine，严禁用模型返回值覆盖确定性结论。建议层在 bridge_report/advisor：measures.py 是失效模式与加固措施规则库（只写定性描述与规范名称，不写数值），diagnose.py 在判定结果上做归类、裕度排序、加固前后对比、下一步工作与建议书数值核对。应用场景定义在 static/js/presets.js。

新增桥梁时按 contracts 当前 Schema 提供 handoff.json，图件用相对路径且留在交接包内。保留每项检查的来源、定位、单位、模型修订和配对内力。53K 的 extraction-map.json 记录 62 项检查的源表、源行及数值列；tools/extract_53k.py 可从仓库中的原始 DOCX 重建。

重新生成三维示例：python tools/prepare_visuals.py <包含两个原始桥梁资料文件夹的目录>。运行本系统不需要这些原始 SAP / PDF 文件，预览已经包含在 examples/visuals。

## 测试

python -m unittest discover 覆盖判定、合同、Word 构建、服务隔离、协议工具调用及资产解析。真实 Word 专项测试需 BRIDGE_TEST_WORD=1，且本机已安装 Word。tools/ui_check.py 是独立无头 Edge 回归工具；需要运行中的服务，参数见 --help。

更新模型依赖时，应再次运行 tests.test_upgrade 的实际 SDK 模拟 HTTP 测试。远端模型连接测试是一次真实计费可能发生的请求；失败不自动重试。未使用项目资料做远端付费测试。
